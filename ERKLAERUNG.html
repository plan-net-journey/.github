Warum wir GitHub nutzen

Unser Setup fuer kollaborative Entwicklung von Skills, Agents und Projekt-Assets bei Plan Net Journey.

Das Problem

Warum aendern wir ueberhaupt etwas?

Unsere bisherige Arbeitsweise mit KI-Tools hat Grenzen, die uns bremsen.

Bisher

  • Jeder arbeitet mit eigenen Prompts und Einstellungen
  • Skills und Wissen gehen verloren wenn jemand geht
  • Keine Versionierung — was weg ist, ist weg
  • Dateien per Mail/Slack hin und her schicken
  • Kein gemeinsamer Wissensstand
vs.

Mit GitHub + Claude Code

  • Skills und Agents als Code — teilbar, versioniert, nachvollziehbar
  • Alles lokal gespeichert und im Team geteilt
  • Jede Aenderung nachvollziehbar (wer, wann, warum)
  • Grosse Dateien ueber Cloud-Storage verlinkt
  • 50+ fertige Skills im Marketplace
Die Bausteine

Was wir nutzen und warum

Vier Werkzeuge, jedes mit einem klaren Zweck.

⚙ GitHub

Was: Plattform auf der unser Code und unsere Skills leben.

Warum: Industriestandard fuer Versionierung. Jede Aenderung ist nachvollziehbar, nichts geht verloren, und alle arbeiten auf dem gleichen Stand.

⌨ Claude Code

Was: KI-Assistent der direkt mit deinen Dateien arbeitet.

Warum: Anders als Claude Desktop kann Claude Code Dateien lesen, bearbeiten und Befehle ausfuehren. Projektkontext bleibt lokal und wird mit git versioniert.

🔑 SSH Keys

Was: Verschluesselter Zugang zu GitHub ohne Passwort.

Warum: Sicherer als Passwoerter, funktioniert automatisch, wird einmal eingerichtet und laeuft dann. Standard in der Softwareentwicklung.

📦 Cloud-Storage Symlinks

Was: Grosse Dateien (Videos, PPTX) bleiben in Box/OneDrive, das Projekt verlinkt darauf.

Warum: Git ist nicht fuer grosse Binaerdateien gemacht. Cloud-Storage kann das besser — und eure Dateien sind dort schon.

Alles per Ticket

Wie funktioniert ein Ticket?

Egal ob Org-Zugang, neues Repo oder Berechtigungen — der Ablauf ist immer gleich:

1 Ticket erstellen

Du fuellst ein Formular auf GitHub aus. Kein Freitext — klare Felder fuer das was gebraucht wird.

↓

2 Admin wird benachrichtigt

Der Admin bekommt automatisch eine E-Mail von GitHub. Kein Slack, kein Anrufen noetig.

↓

3 Admin gibt frei

Der Admin antwortet auf die E-Mail mit /approve. Ein Wort — fertig.

↓

4 Automation laeuft

GitHub fuehrt die Aktion automatisch aus: Einladung verschicken, Repo erstellen, Zugang setzen. Kein manueller Schritt.

↓

5 Ticket schliesst sich

Das Ticket wird automatisch geschlossen mit einer Zusammenfassung was passiert ist. Alles dokumentiert.

Vier Ticket-Typen

Org-Zugang

Neues Teammitglied braucht Zugang zur Organisation.

Neues Repo

Neues Kundenprojekt? Privates Repo wird automatisch mit Template erstellt.

Repo-Zugang

Schreibzugang zu einem bestehenden Repo oder dem Marketplace.

Was sind Skills?

Claude Code: Skills, Agents und Projekt-Kontext

Claude Code ist mehr als ein Chatbot — es ist ein Arbeitsumfeld das sich an euer Projekt anpasst.

Skills

Wiederverwendbare Anweisungen fuer haeufige Aufgaben. Wie Rezepte die Claude befolgt.

Beispiel: /campaign startet die Kampagnenplanung mit dem richtigen Framework und den richtigen Fragen.

Aufruf: /skill-name in Claude Code eingeben.

Agents

Spezialisierte KI-Persoenlichkeiten fuer bestimmte Arbeitsweisen.

Beispiel: Der Rook-Agent ist ein kontraerer Stratege der eure Ideen auf Schwachstellen prueft.

Wechsel: switch to Rook in Claude Code sagen.

Projekt-Kontext

Claude liest automatisch die CLAUDE.md im Projekt und versteht den Kontext.

Beispiel: Wer ist der Kunde, welche Regeln gelten, wo liegen die Dateien.

Claude merkt sich auch Dinge zwischen Sessions ueber MEMORY.md.

Warum ist das besser als einzelne Prompts?

Ein Prompt geht verloren. Ein Skill ist versioniert, geteilt, getestet und verbessert sich ueber die Zeit. Wenn jemand einen besseren Weg findet eine Kampagne zu planen, profitieren alle — nicht nur die eine Person.

Muss ich programmieren koennen?

Nein. Skills sind Markdown-Dateien mit Anweisungen in natuerlicher Sprache. Wer einen klaren Brief schreiben kann, kann einen Skill schreiben. Claude Code hilft dabei.

Regeln

Das gilt fuer alle

Immer

✓ Alle Repos sind privat
✓ SSH Keys fuer Git-Zugang
✓ Neue Repos nur per Ticket
✓ Grosse Dateien per Symlink, nie ins Repo
✓ Aenderungen per Pull Request

Nie

✗ Oeffentliche Repos erstellen
✗ Passwoerter / Tokens committen
✗ Videos oder PPTX ins Repo
✗ Direkt auf main pushen
✗ Skills mit Kundendaten in den Marketplace
