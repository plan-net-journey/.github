Maintainer Handbuch

Wie das PNJ GitHub Setup intern funktioniert — Architektur, Workflows, Regeln.

Architektur

Repos und ihre Aufgaben

Jedes Repo hat eine klare Rolle. Kein Repo macht alles.

.github PUBLIC

Onboarding, Access Requests, ERKLAERUNG.html, GitHub Pages. Einziges oeffentliches Repo — nur fuer den Einstieg neuer User.

admin-ops PRIVAT

Admin-Skills, Tickets (Repo-Request, Zugang, Feedback, Verbesserung), Tests, Memory, Entscheidungen.

Journey-Skills PRIVAT

Plugin Marketplace. Enthaelt das pnj Plugin und kuenftig weitere fachliche Plugins.

project-template PRIVAT

Vorlage fuer neue Repos. CLAUDE.md, .gitignore, MEMORY.md, .cursorrules, AGENTS.md. Wird per Ticket automatisch angewendet.

Kunden-Repos PRIVAT

Pro Kunde/Projekt ein Repo. Wird aus dem Template erstellt. Projektspezifische Skills leben dort, nicht im Marketplace.

Ticket-Flow

Was passiert wenn ein Ticket erstellt wird

Zwei Workflows: Ticket Review (bei Erstellung) und Slash Approve (bei /approve).

Phase 1: Ticket wird erstellt

1 Issue erstellt

User fuellt Formular aus. Label wird automatisch gesetzt (access-request, repo-request, etc.).

↓

2 Ticket Review Workflow

Parst den Issue-Body, erstellt eine Zusammenfassung als Kommentar. Bei Repo-Requests: AI Duplikat-Check via DeepSeek (Prompt liegt in prompts/duplikat-check.md).

↓

3 Teams-Notification

Adaptive Card im privaten Teams-Channel. Zeigt Typ, Autor, Details, AI-Ergebnis, Link zum Issue.

Phase 2: Maintainer gibt frei

4 /approve Comment

Maintainer kommentiert /approve. Nur OWNER, MEMBER oder COLLABORATOR koennen das.

↓

5 Slash Approve Workflow

Erkennt Ticket-Typ (Label oder Titel). Fuehrt die Aktion aus: Org-Einladung, Repo-Erstellung (aus Template + Auto-Team), oder Berechtigungen setzen. Nutzt ORG_ADMIN_TOKEN.

↓

6 Issue geschlossen

Bestaetigungskommentar mit Zusammenfassung + Links zu weiteren Ticket-Typen. Issue wird automatisch geschlossen.

Admin-Skills

Dein Werkzeugkasten

Klone admin-ops, oeffne Claude Code dort, und nutze diese Skills:

SkillWas er tut
/ticket-bearbeitenOffene Tickets anzeigen und mit /approve freigeben
/user-verwaltenMembers, Collaborators und Teams verwalten
/repo-verwaltenRepos erstellen, loeschen, Berechtigungen setzen
/token-verwaltenORG_ADMIN_TOKEN pruefen und erneuern
/org-statusGesamtueberblick: Members, Teams, Repos, offene Tickets

So startest du

gh repo clone plan-net-journey/admin-ops — dann Claude Code im Ordner oeffnen. Claude holt sich automatisch die neueste Version und zeigt offene Tickets.

Plugin Marketplace

Skills verwalten und verteilen

Journey-Skills ist ein nativer Claude Code Marketplace. Plugins werden per /plugin install installiert.

Neues Plugin erstellen

1. Feature Branch: git checkout -b plugin/name
2. Verzeichnis: plugins/name/.claude-plugin/plugin.json + skills/
3. In marketplace.json eintragen
4. Validieren: claude plugin validate
5. PR auf main erstellen

Versionierung (Semver)

Patch (1.0.1): Bugfix, Formulierung
Minor (1.1.0): Neuer Skill
Major (2.0.0): Breaking Change

Version in plugin.json UND marketplace.json synchron bumpen.

Deprecation

Nie loeschen — immer behalten als Referenz. Major Bump, "DEPRECATED" in Description, Migration-Hinweis in README.

Tests

39 automatische Checks

bash tests/verify-setup.sh im admin-ops Repo. Prueft alles: Repos, Templates, Labels, Secrets, Teams, Workflow-Syntax.

Regeln bei Aenderungen

1. Bestehende Tests ausfuehren: bash tests/verify-setup.sh
2. Tests ergaenzen falls die Aenderung neue pruefbare Bedingungen einfuehrt
3. Nicht committen wenn Tests fehlschlagen
4. Jeden Ticket-Typ testen — nicht nur den der geaendert wurde

Learnings

Aus Fehlern gelernt

Fuenf Regeln die aus Produktions-Bugs abgeleitet wurden.

Immer

✓ Automatische Daten statt User-Eingaben verwenden (Issue-Autor statt Formularfeld)

✓ Jeden Ticket-Typ testen, nicht nur den Sonnenschein-Fall

✓ JavaScript fuer JSON, kein Bash/jq

Nach Refactoring

✓ Alle process.env.* vorhanden im env: Block?

✓ Alle steps.*.outputs.* existieren?

✓ Workflow fuer JEDEN Ticket-Typ getestet?

✓ Vor Shipping: Nicht-Techniker testen lassen
